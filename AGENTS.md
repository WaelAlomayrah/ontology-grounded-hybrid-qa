# Agent Guide

## Purpose

This repository is a CPU-first, single-machine research pilot for ontology-driven question answering. FastAPI orchestrates RDF graph retrieval from Fuseki, semantic retrieval from Milvus, and evidence-grounded generation through Ollama. React is the only user-facing client.

## Architecture boundaries

- The frontend may call only the backend HTTP API.
- Fuseki is the authoritative graph and ontology source of truth.
- Milvus is a rebuildable, derived semantic index.
- Never execute raw SPARQL generated by an LLM or supplied by a user.
- Use validated plans and pre-written SPARQL templates with escaped values.
- Ingestion must remain deterministic and idempotent in both reset and append modes.
- Every change must preserve CPU-only operation in base `compose.yaml`; GPU support belongs in `compose.gpu.yaml`.

## Conventions

- Python 3.12, type annotations on public functions, Pydantic v2 models, async HTTP clients.
- Keep API, orchestration, retrieval, and infrastructure clients separate.
- TypeScript strict mode; frontend credentials are forbidden.
- Structured logs must not contain secrets, full prompts, or raw questions.
- Preserve bounded graph traversal and input/result size limits.

## Commands

`make lint`, `make typecheck`, `make test`, `make test-integration`, `make build`, `make up`, `make ingest-sample`, `make smoke-test`, and `make evaluate`.

## Tests and safety

Run unit tests and relevant builds after every material change. Integration tests are marked and require Docker services. Never commit `.env`, credentials, model data, generated evaluation results, or external datasets. Destructive ingestion endpoints require the development admin token.
